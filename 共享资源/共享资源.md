植株株高、冠幅与果实随机化（测试参数，真实温室尺寸待定）

首次使用先构建资产与启动入口：

```bash
cd "/home/hgzq/Agricultural Bot/Agricultural_Bot"
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
cd sim_ws
colcon build --symlink-install --packages-select agri_greenhouse_worlds agri_sim_bringup
source install/setup.bash
cd ..

python3 sim_ws/src/agri_greenhouse_worlds/scripts/generate_tomato_field.py \
  --randomize-fruits --fruit-visual mesh \
  --plant-height 2.0 --plant-width 1.0 \
  --rows 2 --plants-per-row 3 --origin-x -1 --origin-y -5 \
  --fruit-count-min 2 --fruit-count-max 5 \
  --fruit-height-min 0.80 --fruit-height-max 1.60 \
  --fruit-diameter-min 0.06 --fruit-diameter-max 0.09 \
  --seed 42 \
  --output artifacts/tomato_random_demo.sdf \
  --metadata artifacts/tomato_random_demo.json

export ROS_DOMAIN_ID=94
export GZ_PARTITION=agricultural_bot_random_fruits
ros2 launch agri_sim_bringup tomato_field.launch.py \
  world:="$PWD/artifacts/tomato_random_demo.sdf" \
  gz_partition:="$GZ_PARTITION" gui:=true paused:=true
```

此例株高为 2 m、冠幅为 1 m，果实中心离地 0.80–1.60 m，果径 0.06–0.09 m。
`--plant-height` 只调整枝叶竖向尺寸，省略 `--plant-width` 时保留原冠幅；
茎杆碰撞体及果实净空检查同步新尺寸，果实大小、结果高度和水平分布范围独立配置。
果实高度指果实中心距离世界地面 Z=0 的高度，单位米。更换 `--seed` 可生成新分布；
同参数同种子可复现。删除行数、每行株数和两个 origin 覆盖项，可生成原布局 150 株。
果实为独立静态目标，目前没有摘取/脱落物理；修改参数后重新生成并重启对应 Gazebo。
现在默认使用原番茄果体网格和红/青贴图；旧球体场景需要重新生成并重启 Gazebo。
`--fruit-visual sphere` 可切回纯色球体，不改变相同种子下的数量和位置。
完整参数、成熟概率和模型说明见
[植株尺寸与果实参数化指南](../Agricultural_Bot/docs/tomato_fruit_randomization.md)。

| 可修改内容 | 参数 | 默认值 / 含义 |
|---|---|---|
| 植株行数 | `--rows` | `10` |
| 每行株数 | `--plants-per-row` | `15`，总株数＝行数×每行株数 |
| 行距 | `--row-spacing` | `2.0` 米，沿世界 **X** 方向排列各行 |
| 株距 | `--plant-spacing` | `0.7` 米，沿世界 **Y** 方向排列每行植株 |
| 第一株的位置 | `--origin-x`、`--origin-y` | `-9.0`、`-5.0` 米 |
| 地面尺寸 | `--ground-x`、`--ground-y` | `22`、`14` 米，地面以世界原点居中 |
| 枝叶株高 | `--plant-height` | 省略时为 `1.298104` 米；冠顶离地高度，只缩放 Z 轴 |
| 枝叶冠幅 | `--plant-width` | 省略时为 `0.866695` 米；偏航前 X/Y 包围盒最大跨度，与株高独立 |
| 植株朝向扰动 | `--yaw-jitter` | `0.12` rad，随机范围为 ±0.12；设为 `0` 可统一朝向 |
| 启用独立随机果实 | `--randomize-fruits` | 必须加入此开关，下面的果实参数才参与生成 |
| 每株果实数量 | `--fruit-count-min`、`--fruit-count-max` | `2–6` 个，包含上下限 |
| 果实中心高度 | `--fruit-height-min`、`--fruit-height-max` | `0.60–1.10` 米，以世界地面 Z=0 为基准 |
| 果实尺寸 | `--fruit-diameter-min`、`--fruit-diameter-max` | `0.06–0.09` 米，指包围球直径，网格等比例缩放 |
| 果实水平分布 | `--fruit-radius-min`、`--fruit-radius-max` | `0.12–0.25` 米，指果实中心到茎杆中心的水平距离 |
| 最小净间距 | `--fruit-min-clearance` | `0.01` 米，检查果实碰撞球、地面及简化茎杆 |
| 成熟概率 | `--ripe-ratio` | `0.7`；`1` 全红、`0` 全青，不保证实际比例恰好为 70% |
| 果实显示模型 | `--fruit-visual` | `mesh` 使用原果形和贴图；`sphere` 使用纯色球 |
| 随机种子 | `--seed` | `42`；同参数、同种子可复现数量、位置和成熟状态 |
| 世界名称 | `--world-name` | `field` |
| 世界输出路径 | `--output` | 建议显式指定到 `artifacts/`，避免覆盖基线 |
| 标注输出路径 | `--metadata` | 可选 JSON，保存生成参数和逐果位置、尺寸、成熟状态 |

### 预设停车点的迁移原则

参考 `ysftzc/robot_workspaces` 时，停车点来自固定地图上的人工调试 YAML 航点：每个点
记录 map 坐标 `x/y/yaw`，并可附带 `row_id`、作业侧、`view` 和 `arm_pose` 标签；任务层
逐点发送 `NavigateToPose`，到站后才触发扫描/采摘。它不是由 YOLO 果实位置实时反推的
底盘优化结果，也不能直接复制对方的 world/map 偏置。

当前参数化番茄田默认行沿世界 Y 方向、行中心沿 X 方向按 2.0 m 行距排列。后续站点生成
应先把行布局通过已保存地图的对齐变换转换到 map，再扣除底盘 footprint 半宽和安全裕量，
检查代价地图、四舵轮转弯、D405 视场和 CR5 IK 后写入 `waypoints.yaml`。只改变果实数量/结果
高度通常不需移动底盘站点；改变行距、冠幅或株高导致通道变化时必须重新生成并验证。
到站后按 `STOPPING → BASE_LOCKED → SCANNING` 进行速度反馈停稳和 `/base_motion/set_lock`，
不能只依据导航 Action 的 success 状态展开机械臂。

仿真入口把当前 world 的 Gazebo 时钟（基线场景为 `/world/field/clock`）以
`CLOCK` QoS 桥接到 ROS `/clock`。若 RViz 连续提示 `Detected jump back in time`，
在仿真终端检查 ROS 与 Gazebo 两侧：

```bash
ros2 topic info /clock --verbose --no-daemon --spin-time 8
gz topic -l | rg '^/clock$|^/world/.*/clock$'
gz topic -i -t /world/field/clock
```

ROS 输出的 `Publisher count` 必须为 `1`，发布节点应为 `/clock_bridge`，QoS 应是
best effort、volatile、depth 1；Gazebo world 时钟也应只有一个 publisher 地址。
仅有 ROS `Publisher count: 1` 不能排除 bridge 上游混入多个 Gazebo 时钟。自定义 SDF
若使用其他 world 名称，请把检查命令中的 `field` 换成 `gz topic -l` 列出的名称。
若 ROS 侧存在旧 bridge，在仿真和导航终端统一换一个未使用的 `ROS_DOMAIN_ID`。
