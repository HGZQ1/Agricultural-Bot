3. 单轮运动学

每个舵轮有两个状态：

· δ_i：转向角，轮子平面相对底盘 x 轴的角度，单位 rad；
· ω_wheel_i：驱动轮角速度，单位 rad/s。

轮子半径 R = 0.127 m，则轮子线速度：

```text
v_i = R * ω_wheel_i
```

δ_i = 0 表示轮子朝正前方。
左右镜像安装时，控制器内部会加 180° 偏移，视觉同学不用管，知道“零位朝前”即可。

---

4. 四舵轮逆运动学（核心）

底盘控制器收到速度指令：

```text
V = (vx, vy, ωz)
```

含义：

· vx：向前速度，m/s
· vy：向左速度，m/s
· ωz：逆时针角速度，rad/s

对每个轮子，先算轮心处的期望速度：

```text
v_ix = vx - ωz * y_i
v_iy = vy + ωz * x_i
```

其中 x_i, y_i 用米。

然后算两个量：

轮子速度大小：

```text
s_i = sqrt(v_ix^2 + v_iy^2)
```

轮子朝向角：

```text
δ_i = atan2(v_iy, v_ix)
```

最后发给舵轮模块：

```text
转向角 = δ_i
驱动轮角速度 = s_i / R
```

如果 δ_i 超出机械限位，常用技巧是：

轮子反向 + 角度转 180°。
因为轮子可以双向滚，所以 δ_i + π 且速度取反，等效方向不变。

5. 常见运动模式

模式 指令 四轮表现 需要的转向角
直行 vx>0, vy=0, ωz=0 四轮 δ=0，同速前进 0°
小角度斜行 vx>0, vy>0, ωz=0 四轮同角度，沿斜线平移 atan(vy/vx)
横移 vx=0, vy>0, ωz=0 四轮 δ=90°，同速左移 90°
原地左转 vx=0, vy=0, ωz>0 四轮指向各自切向，速度大小与到中心距离成正比 约 129°

用你的尺寸算原地旋转：

以左前轮为例：

```text
v_ix = -ωz * 0.182025
v_iy =  ωz * 0.224995
δ_FL = atan2(0.224995, -0.182025) ≈ 129°
```

也就是说，原地旋转需要转向角约 129°。

6. 关键提醒：必须确认舵轮最大转向角

请务必向硬件确认：舵轮机械限位是多少？

· 如果限位是 ±90° 或更大：可以横移、斜行、原地旋转。
· 如果限位只有 ±25°：
  · 直行：可以
  · 小角度斜行：可以，但 vy/vx ≤ tan(25°) ≈ 0.466
  · 横移：不可用
  · 原地旋转：不可用
  · 视觉不要依赖底盘横移或原地转来对准目标，只能靠路径规划和小角度纠偏。

7. URDF 中四舵轮关节填写示例

每个轮组建模为两个关节：

· 转向关节 steer_joint：revolute，绕 z 轴，限位按实际填写；
· 驱动关节 wheel_joint：continuous，绕轮轴。

以左前轮为例：

```xml
<!-- 左前转向关节 -->
<joint name="fl_steer_joint" type="revolute">
  <parent link="base_link"/>
  <child link="fl_steer_link"/>
  <origin xyz="0.224995 0.182025 0" rpy="0 0 0"/>
  <axis xyz="0 0 1"/>
  <limit lower="-0.4363" upper="0.4363" effort="10" velocity="1.0"/>
</joint>

<!-- 左前驱动关节 -->
<joint name="fl_wheel_joint" type="continuous">
  <parent link="fl_steer_link"/>
  <child link="fl_wheel_link"/>
  <origin xyz="0 0 0" rpy="0 0 0"/>
  <axis xyz="0 1 0"/>
</joint>
```

说明：

· origin xyz 是转向关节在 base_link 下的位置，已按实际参数填写；
· limit lower/upper 示例为 ±25°（±0.4363 rad），请替换为实际舵轮限位；
· 驱动关节 origin 通常为 0 0 0，轮子中心与转向关节重合；
· 右前、左后、右后轮同理，只改 origin 的 x, y 符号。

轮子 origin xyz

右前 FR 0.224995 -0.182025 0

8. TF 树结构

```text
odom
└── base_link
    ├── fl_steer_link
    │   └── fl_wheel_link
    ├── fr_steer_link
    │   └── fr_wheel_link
    ├── rl_steer_link
    │   └── rl_wheel_link
    ├── rr_steer_link
    │   └── rr_wheel_link
    ├── cr5_base_link
    │   └── ... CR5关节链
    ├── mid360_link
    ├── camera_link
    └── basket_link
```

· odom -> base_link：由底盘运动学或轮式里程计发布，动态变化；
· base_link -> fl_steer_link：固定变换，由 URDF 决定；
· fl_steer_link -> fl_wheel_link：转向角动态变化；
· base_link -> cr5_base_link：固定变换，机械臂基座安装位置；
· base_link -> camera_link：固定变换，相机安装位置。

---

9. 给视觉同学的 5 个要点

1. 相机到 base_link 是固定变换
   由 URDF 决定，不随舵轮转动变化。
2. 机械臂基座 cr5_base_link 也固定在 base_link 上
   所以只要底盘停稳，视觉给出的 P_base 就可以直接用于抓取。
3. 底盘运动由 odom -> base_link 反映
   移动中做视觉，要用 odom 补偿底盘运动，否则目标在 base_link 下的坐标会一直变。
4. 手眼标定与舵轮无关
   标定的是 camera_link -> cr5_base_link 的固定变换。
5. 抓取时建议停稳拍照
   减少运动模糊和坐标跳动；舵轮转向时底盘可能有横摆，等转向完成后再触发检测。

---

10. 三句话总结

1. 视觉只管把目标从 camera_link 变到 base_link，再变到 cr5_base_link。
2. 底盘怎么动，由舵轮控制器负责；视觉不需要算轮子角度，但要知道 odom -> base_link 会随底盘运动变化。
3. 抓取时底盘停稳，视觉拍照，坐标给 MoveIt2；移动中做视觉就要用 odom 补偿。
